## 1. Environment and dependencies

Check the installed mainline packages:

~~~powershell
& $PY -c "import robosuite, mujoco, numpy, cv2, mediapipe, hid; print(robosuite.__version__, mujoco.__version__, numpy.__version__)"
~~~

Synchronize the locked dependencies:

~~~powershell
& $PY -m pip install -r .\requirements-robosuite-wrist.lock
~~~

The main robosuite process does not directly install dex-retargeting. Its native pin>=2.7 dependencies are not reliably co-installable with the current Windows MuJoCo environment. Panda + Allegro launches a separate Python sidecar that loads the checked official dex-retargeting 0.4.6 wheel, receives 21 x 3 MANO landmarks through newline-delimited JSON, and returns 16 named Allegro targets.

With runtime=auto, the application looks for dexretarget\python.exe next to the base Conda environment. If your isolated dex environment is elsewhere, set it before startup:

~~~powershell
$env:DEX_RETARGETING_PYTHON = "D:\your-dex-environment\python.exe"
~~~

Only the sidecar sets KMP_DUPLICATE_LIB_OK=TRUE for the current Conda OpenMP DLL collision. The robosuite / MuJoCo process is not modified.

## 2. SpaceMouse diagnostic

Direction calibration (run once per device, about 40 s): it asks for six held gestures with the logo facing you (push away, push right, lift, tilt the top away, tilt the top right, twist clockwise) and writes axis_order / axis_inversion into configs\spacemouse_wrist.json after backing it up to outputs\spacemouse_axis_calibration. Every robosuite and LIBERO entry reads the same file.

~~~powershell
& $PY .\scripts\calibrate_spacemouse_axes.py
& $PY .\scripts\calibrate_spacemouse_axes.py --dry-run
~~~

By default only the stronger of the translation / rotation groups is passed each step (motion_coupling "dominant", dominant_switch_ratio, axis_snap_ratio in the config), so pushing the cap does not also rotate the hand. Set "motion_coupling": "combined" for simultaneous translation and rotation.


The diagnostic reports device discovery, raw six-axis values, calibrated values, offset, deadzone and smoothing output, final OSC action, button states, frequency, and disconnect errors. Keep the device centered during the initial eight-frame neutral calibration. Missing, stale, or disconnected input produces an exact zero action.

~~~powershell
& $PY .\scripts\run_spacemouse_panda_wrist_teleop.py diagnostic
& $PY .\scripts\run_spacemouse_panda_wrist_teleop.py diagnostic --duration 30
~~~

In 3DxWare, disable mouse-wheel emulation, system clicks, radial menus, and driver UI actions. Inspect, install, or restore the project profile:

~~~powershell
& $PY .\scripts\manage_3dxware_profile.py inspect
& .\scripts\install_3dxware_spacemouse_profile.ps1
& .\scripts\restore_3dxware_spacemouse_profile.ps1 -Manifest <backup-manifest-path>
~~~

## 5.1 Official LIBERO Spatial teleoperation

LIBERO uses its own isolated interpreter: Python 3.8, robosuite 1.4, and MuJoCo 3.2.3. Do not run these two files with `.venv-robosuite`, and do not install the LIBERO dependencies into the mainline environment.

~~~powershell
$LIBERO_PY = ".\.venv-libero\Scripts\python.exe"
& $LIBERO_PY -m pip install -r .\requirements-libero-teleop.lock

# Panda + Shadow Hand: SpaceMouse controls only the six Panda OSC dimensions;
# the camera drives Shadow through official dex-retargeting DexPilot by default.
# The dex sidecar takes ~60 s on first launch. --hand-control legacy-curl keeps
# the old rule-based mapper.
& $LIBERO_PY .\scripts\run_libero_spatial_panda_shadow_teleop.py

# Arm speed defaults to 3.0x translation / 2.0x rotation (raised from 2.5 / 1.6
# on 2026-10-28); tune per run:
& $LIBERO_PY .\scripts\run_libero_spatial_panda_shadow_teleop.py --arm-speed 4 --rot-speed 2.5

# Shadow hand turned on the flange so the fingers point straight down at the
# start pose (default: fingers forward, palm down). Also for the camera-only entry.
& $LIBERO_PY .\scripts\run_libero_spatial_panda_shadow_teleop.py --hand-mount down

# Heavier task objects: every BDDL object's mass and inertia x N (LIBERO's
# objects weigh 5-30 g; x10 gives a 260 g soup can). Printed at startup.
# All three LIBERO entries.
& $LIBERO_PY .\scripts\run_libero_spatial_panda_shadow_teleop.py --suite libero_object --task-id 0 --object-mass-scale 10

# Thumb lift gain: how much the thumb's lift off the palm (toward the camera)
# is amplified (default 1.5, 1 = as the camera measures it). Both Shadow entries.
& $LIBERO_PY .\scripts\run_libero_spatial_panda_shadow_teleop.py --thumb-lift-gain 1.8

# Fingers through the unmodified official DexPilot (for comparison; the
# default adds the project mapping terms, see below).
& $LIBERO_PY .\scripts\run_libero_spatial_panda_shadow_teleop.py --dex-official

# Change only the released official Spatial task selection when required.
& $LIBERO_PY .\scripts\run_libero_spatial_panda_shadow_teleop.py --task-id 1 --init-state-id 0

# Other official suites (both LIBERO entries): --suite libero_object |
# libero_goal | libero_10 | libero_90, then --task-id inside that suite. The
# main and side cameras move with the robot base, so every suite gets the
# same view as Spatial (libero_object puts the robot on the floor).
& $LIBERO_PY .\scripts\run_libero_spatial_panda_shadow_teleop.py --suite libero_object --task-id 4
~~~

The adapter loads the released LIBERO BDDL and its official default-Panda state. The saved state cannot be copied as one vector after changing the gripper, so the adapter copies only compatible named Panda / object joints and lets the selected hand start in its own safe configuration. This preserves the official scene without falsely claiming that an alternative hand can load the default-gripper state byte-for-byte.

The LIBERO adapter holds its own desired end-effector pose (robosuite 1.4 OSC otherwise re-anchors to the current pose every step and drifts), uses a flange-rigid OSC point for Shadow (OSC kp 500 since 2026-10-28, was 300) and rebinds the laser after R (hard reset).

Simulator window (since 2026-10-28, all LIBERO entries): one window filling the primary monitor, shown 1:1 (the process is DPI-aware, so Windows no longer stretches and blurs it; --view-size WxH picks another size). Left: the fixed main view (a little tighter than before). Upper right: a close-up that follows the hand from the main camera's side, so the gap between fingers, thumb and object is visible during the grasp (the old palm camera was covered by the object); V turns it 90 deg around the hand, e.g. to the thumb side. Lower right: a 3D view that follows the hand from the front-right, at right angles to the main view, for depth; the arm is behind the hand there and never covers it. The webcam preview is drawn bottom-left in the main view. Drawing runs on its own thread from scene snapshots taken after each step and once mid-step: the control loop holds 20 Hz (it measured 10.6 Hz with the old renderer in libero_10) and the display runs at about 35-40 fps. The exit line prints both.

Shadow fingers (dex): official DexPilot plus a project mapping (configs/dex_retargeting/shadow_grasp_terms.json, updated 2026-11-04). Every term reads only the operator's landmarks in the current frame; nothing looks at objects, and there is no preset or snapping. (1) Posture: the operator's thumb and finger segment directions are extra targets, so lateral grips and power wraps keep the operator's thumb posture. (2) Thumb lift gain: lifting the thumb off the palm to bring it in front of the fingers moves it toward the camera, and the camera underestimates depth; the thumb's offset from the operator's palm plane is multiplied by --thumb-lift-gain (default 1.5, 1 = as measured). A thumb lying in the palm plane is unaffected. (3) Per-finger length: each finger's palm part (wrist to MCP) and finger part (MCP to tip) are scaled to the Shadow lengths, measured from the landmarks every frame, so a straight finger maps to a straight finger (with one shared scale the short little finger stayed bent when the hand was flat). (4) Pinch: official DexPilot snaps thumb and fingertip together below 3 cm and lets go above 5 cm; instead the robot thumb-to-finger distance is always 1.2 x (operator distance - 1 cm), along the operator's direction, so it closes when the operator's pads touch and opens in proportion, with no threshold. Synthetic grasps: flat hand little finger 0.97 -> 1.01 of its straight reach; pinch closes to 4-5 mm; a tight lateral grip keeps its 18 mm thumb-to-tip gap (official snaps to 2 mm); with depth compressed to 60 % the thumb lift (THJ4) recovers from 24/36 deg to 32/45 deg at 30/45 deg of operator lift. Each run logs the operator's 21 landmarks and the per-frame scales (camera_details in telemetry.jsonl) so the gain and the 1 cm pinch gap can be calibrated from a real session. --dex-official runs the unmodified DexPilot for comparison.

## 5.2 LIBERO Spatial camera-only teleoperation (Panda + Shadow, no SpaceMouse)

Your RIGHT hand in front of the webcam drives the arm and the Shadow fingers (DexPilot). Show an open right hand, palm toward the camera, and hold it still; the arm starts after about 1.5 s ("arm: tracking"). Then, like a mouse:
- left/right, up/down and toward/away from the camera: the end effector follows the hand's motion; slow = fine (about 0.5x), fast = farther (up to about 1.8x). A still hand keeps the arm still in every direction (depth is no longer rate controlled, since 2026-10-28);
- turn or tilt the hand: the end effector follows the whole palm rotation (rotation is held while the hand is translating);
- show your LEFT hand next to the right one = clutch: the arm holds while you reposition the right hand.
- after C (pause/resume), a lost hand or R, the overlay shows HOLD STILL until the hand has settled; the arm then continues from where it is, so bringing the hand back into place does not move it.
Keys (simulator window): C pause/resume, - / = gain, R reset, Q quit. A lost hand holds the arm. Nothing assists the grasp automatically.

Display: main view + orthographic top (plan) and side (elevation) views aligned with your directions, a vertical palm laser with the height above the surface, and the webcam preview (safe zone + depth gauge: how far the hand is nearer / farther than where tracking started; yellow = running out of hand travel, use the clutch) embedded bottom-left.

~~~powershell
& $LIBERO_PY .\scripts\run_libero_spatial_panda_shadow_camera_teleop.py
& $LIBERO_PY .\scripts\run_libero_spatial_panda_shadow_camera_teleop.py --gain 0.8 --depth-gain 1.2
& $LIBERO_PY .\scripts\run_libero_spatial_panda_shadow_camera_teleop.py --viewer-smoke
& $LIBERO_PY .\scripts\run_libero_spatial_panda_shadow_camera_teleop.py --headless --headless-smoke
& $LIBERO_PY -m pytest -q .\tests\test_camera_arm_control.py .\tests\test_libero_camera_teleop.py
~~~

Safety layers (they only slow or stop motion, never move the arm by themselves): workspace = task objects' area + 15 cm within the reach box, reach shell, base-axis radius, yaw +/-90 deg / tilt +/-30 deg; a Jacobian-based guard against joint limits and low manipulability that keeps the Panda elbow bent (joint 4 <= -0.82 rad; the stretched-elbow singularity is at about -0.47 rad); a virtual wall after a block that lifts as soon as you move away or a re-check finds the motion safe; and a hold when a target cannot be reached for 1 s. --camera-fov (default 65) only scales the metric hand estimate. --gain scales all three directions; --depth-gain is an extra factor on toward/away (default 1.0).

This entry uses OSC kp 500 (now the same as the SpaceMouse LIBERO entries) and a 0.30 m/s end-effector speed cap. It shares the threaded 1:1 window, --hand-mount down, --object-mass-scale, --view-size and --dex-official with 5.1; its two small views stay the orthographic plan / elevation views.

## 8. Output, manual checks, and rollback

LIBERO logs are written to outputs\libero\<timestamp>_<entry>\ (metadata.json, telemetry.jsonl with per-step timing and task_success, tri_view_initial.png). Each dex run records its runtime, wheel and config SHA-256, grasp terms and joint names in the metadata. The outputs directory is local evidence and is excluded from Git.

Before accepting live operation, manually verify the live image and landmarks, right-hand dex motion, SpaceMouse direction and neutral behavior, button isolation, R/Q/Ctrl+C cleanup, and a sustained dex sidecar session.

To disable the laser, set laser.enabled to false in configs\spacemouse_wrist.json. To disable the composite, set tri_view.enabled to false or pass --no-three-view. Set dex_hand.runtime to native to forbid the sidecar and require official dex dependencies inside the active interpreter. To use the old rule-based mapping, explicitly pass --hand-control legacy-curl.

Pre-change copies and their SHA-256 manifest are stored locally under outputs\weekly_grasp_ux\20260916T153432Z\prechange\. Restore those copies to revert this iteration.
